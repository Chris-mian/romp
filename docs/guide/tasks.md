# Tasks, not transcripts

Romp turns what each agent does into task cards, so you follow the work by
outcome instead of scrolling transcripts.

The cards are generated automatically: Romp's judges read each session's
transcript as it grows, group the work into tasks, and keep every card's
status and summary current, with no reporting step for the agent and no
filing step for you.

## One card, three depths

The title is the gist. **Background** is why the work exists: what led to it
and whose ask it is. **Summary** is what the agent did, written to stand on
its own. Sub-tasks nest beneath when the work splits. Each level is one
click, so you spend attention only where the work earns it.

![The anatomy of a task card](../assets/guide/card-anatomy.png){ width="100%" }

## Tasks follow the work, not the session

A session that interleaves several efforts gets a card per effort, and one
effort handed across sessions stays a single card. Ownership and status ride
along, so a handoff never drops a thread.

## Coming back to a thread

Summaries favor the latest stretch of work, so a card you return to after
hours away tells you what changed since you last looked. When you're done
with a card, **Clear** it (**Undo clear** brings it back); cleared cards are
archived.
